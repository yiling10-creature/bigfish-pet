# 素材来源与读取方式

本文件说明桌宠**从哪里拿角色美术、怎么拿、拿不到怎么办**。仓库不存储任何素材。

## 1. 为什么素材不在仓库里

上游 `dsh-bigfish` 的 `NOTICE` 写明：

> The character references were supplied by the user. Original artist/source was not identified in the supplied files.
> No ownership of the original character artwork or DeepSeek trademarks is claimed.
> The code MIT license does not license underlying third-party character rights.

即：**代码是 MIT，角色美术不随之授权**。因此本仓库只放壳与脚本，素材一律从用户本机的插件中读取。

## 2. 素材实际存在哪

上游的 6 张图集以**构建期内联**的方式进入前端包，所以「装好插件」之后，素材有两个可能的落点：

| 落点 | 路径 | 形态 |
| --- | --- | --- |
| A. 已安装插件的客户端包 | `%USERPROFILE%\.dsh\profiles\<profile>\node_modules\dsh-bigfish\lib\client.js` | 6 个 `data:image/png;base64,…` 字面量，合计约 34 MB |
| B. 上游源码仓库 | `<upstream-clone>\packs\classic\*.png` | 6 个原始 PNG，合计约 12.5 MB |

> 注意：**npm 包里的 `packs/classic/` 只有 `manifest.json`，没有 PNG**。所以不能指望"读 packs 目录"拿到图 —— 图在 `lib/client.js` 里。

## 3. 读取顺序（实现约定）

```
1. 环境变量 BIGFISH_PET_ASSETS
      指向一个目录，内含 6 个约定文件名的 PNG（见第 4 节）。调试/自制素材走这条。
2. 已安装插件 A 路径
      读 lib/client.js → 正则抽出 6 个 data URL → 按第 4 节顺序映射到 6 个名字。
3. 上游源码 B 路径
      若用户本地有 upstream clone（默认探测 ..\bigfish-pet\source\packs\classic），直接读 PNG。
4. 都没有
      不崩溃：窗口显示一张说明卡片 + 「如何安装」按钮，日志写清缺哪一项。
```

## 4. 文件名与顺序（固定）

```
bigfish-atlas.png      # 基础姿态
bigfish-motions.png    # 动作帧
bigfish-signs.png      # 举牌
bigfish-work.png       # 工作/工具
bigfish-quiet.png      # 安静陪伴
bigfish-daily.png      # 日常
```

顺序对应上游 `src/contract/builtin-assets.ts` 里的 `builtinAssets` 数组，**不要重排**，否则姿态会错位。

抽取 base64 的正则（Node，`g` 标志）：

```js
/data:image\/png;base64,[A-Za-z0-9+/=]+/g
```

`lib/client.js` 里恰好 6 处，按出现顺序即第 4 节的顺序（构建时按 `builtinAssets` 顺序打包）。

## 5. 注入方式（改造后）

主进程读到图集后，通过 preload 暴露的通道交给渲染进程，渲染进程在启动前把它们挂到全局：

```js
// 伪代码
const assets = await window.desktopPet.getAssets(); // { atlas: 'data:image/png;base64,…', ... }
globalThis.__BIGFISH_ASSETS__ = assets;             // 渲染器优先读这里
```

渲染器侧对应改动：`src/pet/sprite-assets.ts` 里的 `classicPack` 改为「先看 `__BIGFISH_ASSETS__`，没有再用内联常量」。这样构建时可以把 PNG 打桩成 1×1 透明图，产物从 34 MB 降到 1–2 MB。

## 6. 缓存与用户自制素材

| 位置 | 用途 |
| --- | --- |
| `%APPDATA%\BigFishPet\` | 应用数据（位置、偏好） |
| `<exe 目录>\bigfish-profile\` | 便携版回退目录 |
| 设置窗口 → 角色库 | 用户自己导入的 `.dshpet` 角色包，存在 IndexedDB，**不进仓库、不上传** |

## 7. 体积对照

| 方案 | 仓库 | 安装包 | 是否含素材 |
| --- | --- | --- | --- |
| 改造前（现状） | 约 0.5 MB | 约 180 MB | 含（内嵌在 pet.html） |
| 改造后（本文件描述） | 约 0.5 MB | 约 60 MB | 不含，运行时从插件读 |

## 8. 已实现（1.0.7）

素材剥离已经落地，实现分四处：

| 位置 | 改动 |
| --- | --- |
| `patches/sprite-assets.runtime.ts` | 替换上游 `src/client/sprite-assets.ts`：6 张图集改成从 `window.__BIGFISH_ASSETS__` 取，getter 延迟取值 |
| `patches/builtin-extension.runtime.ts` | 替换上游 `src/client/builtin-extension.ts`：13 MB 的 `playful` 扩展包改成运行时 base64 解码 |
| `shell/preload.cjs` | `ipcRenderer.sendSync('bigfish:assets')` → `contextBridge.exposeInMainWorld('__BIGFISH_ASSETS__', assets)` |
| `shell/main.cjs` | `resolvePetAssets()` 按"指定目录 → 插件 `lib/client.js` → 上游源码"顺序解析；缺素材时弹窗并退出 |

`scripts/build-pet.ps1` 在克隆上游后自动应用前两个补丁，并把产物体积 > 3 MB 视为失败（防止补丁失效却悄悄构建出内联版本）。

实测（2026-10-21，Windows 10.0.26200，electron 44.9.2）：

```
pet.html      34.61 MB → 0.39 MB
app.asar      34.88 MB → 0.68 MB
便携版 zip    182 MB   → 147 MB   （剩余体积主要是 Electron 运行时）
包内素材      6 图集 + 1 扩展包 → 0
```
